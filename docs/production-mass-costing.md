# Production material weights and cost

New production forms use calculated output: all selected mass ingredients are converted from kg/g to kilograms, summed, and added to water. Chemistry weight, all-material weight, water weight, and total input weight are stored separately. Calculated output kilograms equal the total input; liters use the saved density snapshot. Moving weighted-average material costs plus extra AFN expenses are divided by that output to derive cost per kilogram. Water has zero purchase cost.

The form checks both overall material stock and received purchase-lot availability. A selected purchase can run out even when other purchases have stock. Package counts are checked separately. The API repeats the checks under transaction/stock locks and returns row-specific shortage errors, so a rejected run cannot consume stock. Package counts must be nonnegative integers.

Storage transfers are limited by calculated output and tank capacity. Existing tank inventory and packing services use production quantity and unit cost, so the same mixture cost flows into packing and finished stock.

`output_from_inputs` distinguishes calculated runs from historical runs with independently measured output. The migration backfills material/chemistry/total-input summaries from saved ingredients while preserving historical output quantities and prices. Editing an old run offers an explicit switch to calculated mixture weight. Existing API clients that send an output quantity retain their original measured-output behavior unless they set this flag. New API requests without output quantities use calculated output automatically.

API and frontend totals round half-up to four decimal places in kg after summing (not per ingredient). Ingredient inventory quantities remain in their configured kg/g unit. Non-mass piece counts cannot be treated as kilograms in calculated-output mode.

Production and packing now save `usd_to_afn_rate` (AFN per USD). USD unit costs are AFN costs divided by this rate, rounded half-up to six decimals. The AFN ledger, weighted-average costs and output valuations remain authoritative. Editing an existing run preserves its saved reporting rate. Migration 0008 fills historical runs using active positive USD rates on or before the transaction's business day; records without an eligible rate retain null and show USD as unavailable. No default or future rate is substituted. Rates added later do not silently change saved runs.

Production lists/details and the production form show cost per kg in both currencies. Packing forms/details show only liquid, packaging and total costs in the summary. A separate stock unit cost section previews the allocation to filled bottle, carton and plastic outputs and reads each saved output unit cost on the details page. Preview package quantities use the actual consumed counts, while bottle costs use the number of filled bottles. The full-run bottle/carton equivalents remain available as legacy reporting values on the API; they are not the three stock output prices. Bottle, carton and plastic output lots retain their existing nonduplicated AFN valuations. Their USD costs use the packing run's saved rate.

Raw stock, tank and finished stock balances show current AFN valuations translated at the current reporting rate; those USD equivalents can change as rates change. Raw stock's price field holds its moving weighted-average AFN cost. Purchase details use the stored invoice rate for USD purchases and a dated reporting lookup for other currencies. Live previews are estimates; saved production/packing costs come from the server's weighted-average calculations. A migration is required before running this version (`python manage.py migrate`).

Raw purchase lines now require a positive unit price. Manual raw stock with a positive quantity or package count also requires an actual positive AFN unit cost, in both the form and API. Production and packing reject unpriced material allocations before consumption; water remains a separate zero-purchase-cost input. This prevents zero-priced opening materials from silently producing undervalued finished stock.

Run `python manage.py repair_raw_material_prices --report raw_material_stock_price_audit.csv` to audit missing raw stock prices. Add `--apply` to recover prices from the latest received purchase for the same material ID, using the purchase's AFN unit cost or its saved currency rate when the AFN field is missing. This changes only missing stock prices and their purchase dates, preserving quantities and existing positive prices. Items without a priced received purchase remain unresolved; the CSV identifies them for actual supplier/opening cost entry. The command does not invent prices or retroactively revalue production, packing, or ledgers.

For explicitly authorized test data, `python manage.py seed_demo_raw_material_prices --apply --report demo_raw_material_prices_applied.csv` assigns deterministic fictional opening costs only to zero-priced raw stock. It preserves existing positive prices, balances and purchase history, labels the material description, and exposes `price_is_sample` for the stock-list badge. Dry run is the default. These values are test fixtures, not market quotations. The local test dataset's affected production and unused packing outputs were recalculated through the existing services after a SQLite backup; `demo_inventory_pricing_result.json` records the changes.

The storage tank list and details share the server's cost per kg: the remaining liquid value divided by actual remaining mass. The list displays `AFN 0.00 | USD 0.00`, using the current reporting rate, and a dash for empty tanks. Quantity formatting remains independent of monetary rounding. Tank valuation counts sales returns once, matching the packing inventory ledger. Per-liter averages are divided as Python Decimals to preserve fractional costs on SQLite.
